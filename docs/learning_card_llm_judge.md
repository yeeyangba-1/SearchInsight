# LLM Judge 学习卡片

## 1. 这个模块做什么？

这个模块只对疑似低质量的 AI 搜索回答做语义复核，判断回答是否真正回答了问题、是否利用了检索内容、是否遗漏关键信息。

## 2. 输入是什么？

输入是 `outputs/analyzed_search_logs.csv` 中已经被规则识别过的搜索日志，重点筛选 Bad Case、用户不满意、检索为空、答非所问、知识库未利用的样本。

## 3. 输出是什么？

输出会进入第 6 个 EVAL Agent 的 `model_result["llm_judge"]` 字段，包含评估来源、候选数量、每条样本的问题归因和优化建议。

## 4. 为什么不是每条都调用大模型？

因为每条都调用成本高、速度慢，也没有必要。先用规则筛出疑似低质量样本，再让 LLM Judge 复核，能兼顾成本和语义判断能力。

## 5. 如果没有 API Key 怎么办？

系统会自动 fallback 到规则评估，页面不会崩溃，仍然能看到 EVAL Agent 的评估结果。

## 6. 面试时一句话怎么讲？

这个模块主要解决的是规则判断语义能力不足的问题，我只对疑似 Bad Case 调用 LLM Judge 做复核，并设计了规则 fallback，既控制成本，也保证系统稳定可运行。
